# DeepSolar Korea · 공개 검증 데모

한국어 태양광 영상 분석 워크플로를 브라우저에서 검증하는 정적 웹 앱입니다.

**데모:** https://biztalk72.github.io/deepsolar-korea-demo/

## 실행되는 기능

- 64 × 64 픽셀 합성 영상 24개 탐색: 학습 16개, 검증 4개, 시험 4개
- 학습 영상의 마스크 검수: 배경 0, 태양광 1, 무효 255
- 가로·세로 축소 배율 1·2·4·8의 면적 평균 열화 실험과 영상 비교
- Web Worker에서 실제로 수행하는 클래스 균형 로지스틱 기준선 학습
- 고정 검증·시험 집합의 정밀도, 재현율, F1, IoU 확인과 실행 결과 비교
- 이 브라우저에 라벨과 실행 결과 보관, 검증 기록 JSON 다운로드

브라우저 합성 실험은 처음에는 학습 결과가 없습니다. 학습을 실행하면 현재 합성 라벨에서 수치가 계산됩니다. 기본 분류 임계값은 0.5입니다. 시험 집합은 학습과 정규화에 사용하지 않습니다.

## 공식 공개 영상의 실제 학습 결과

[공식 샘플 학습 결과](https://biztalk72.github.io/deepsolar-korea-demo/#official)에서 DeepSolar++ 저자가 공개한 실제 영상의 별도 CPU 실험을 확인할 수 있습니다. 공식 예제 전체 68개 중 영상 단위 태양광 유무 라벨이 있는 HR 12개를 사용했습니다. 학습·검증·시험은 각각 4개이고, ImageNet ResNet18 특징 추출기를 고정한 상태에서 513개 파라미터의 분류 헤드를 학습했습니다.

시험 결과는 3/4 정답, precision 0.667, recall 1.000, F1 0.800입니다. 표본이 4개뿐이며 정확도의 Wilson 95% 참고 구간은 약 30.1–95.4%입니다. 한국 정확도나 원본 DeepSolar 재현 결과로 사용할 수 없습니다. 같은 모델에 8배 축소를 적용한 시험에서는 2/4 정답, F1 0.667이었습니다.

이 화면의 결과는 실제 로컬 실험에서 생성된 `real-sample-results.json`을 읽습니다. DeepSolar++ 원본 영상과 외부 모델 가중치는 재게시하지 않습니다. 한국 수집 섹션에는 공개 이용 조건에 따라 출처를 표시한 Sentinel-2 변환 미리보기 6개를 제공합니다. 원본 GeoTIFF는 포함하지 않습니다. 한국 공개 영상의 수집·라벨 준비 상태도 별도로 표시합니다. 미라벨 영상 수집은 한국 태양광 판별 모델의 학습 완료를 뜻하지 않습니다.

공식 자료: https://github.com/wangzhecheng/DeepSolar_timelapse

## 브라우저 실험의 검증 범위

브라우저에서 생성·편집·학습하는 영상과 정답은 코드로 만든 **합성 예제**입니다. 한국 실영상 판별 정확도, 발전소 위치, 설치 용량 또는 투자 수익을 나타내지 않습니다. 화면의 기준선은 원본 DeepSolar CNN이나 서버용 TinyUNet 모델이 아닙니다. 브라우저 모델과 Python 기준선은 별도 구현이며 가중치 교환 형식으로 사용하지 않습니다.

해상도 실험은 합성 RGB 영상의 면적 평균과 최근접 확대입니다. 센서의 실제 MTF, 촬영 조건이나 복구 가능한 정보량을 입증하지 않습니다. 생성된 고해상도 정답 격자를 유지한 픽셀 평가이므로 저해상도 셀의 실제 태양광 점유율 평가와도 구분해야 합니다.

GitHub Pages는 이 앱의 HTML·CSS·JavaScript를 제공합니다. Python/PyTorch 학습, GPU, AWS 작업 실행, 사용자 계정, 공동 라벨 저장소는 서버 배포가 필요한 별도 기능입니다.

## 데이터 처리

합성 실험의 영상 생성, 라벨 수정, 모델 학습과 결과 계산은 브라우저에서 처리합니다. 공식 샘플 결과 페이지는 함께 배포한 실제 실험의 정적 JSON을 읽습니다. 앱에는 업로드 API, 외부 분석 도구 또는 인증정보 입력란이 없습니다. 로컬 기록은 같은 브라우저와 사이트 출처의 저장 공간을 사용합니다. 저장 공간을 지우거나 다른 브라우저에서 열면 기록이 이어지지 않을 수 있습니다. JSON 다운로드는 사용자가 실행한 경우에만 만들어집니다.

GitHub Pages 자체의 HTTP 접근 기록 정책은 GitHub의 개인정보 처리방침을 따릅니다. 앱의 브라우저 내 처리 설명이 호스팅 사업자의 접근 기록까지 없다는 뜻은 아닙니다.

## 로컬 실행

저장소를 내려받은 디렉터리에서 정적 서버를 실행합니다.

```bash
python3 -m http.server 8080
```

브라우저에서 `http://localhost:8080`을 엽니다. ES 모듈과 Worker를 사용하므로 HTML 파일을 파일 탐색기에서 직접 여는 방식은 지원하지 않습니다.

## 배포

`main` 브랜치 루트를 GitHub Pages의 게시 원본으로 사용합니다. `.nojekyll`이 포함되어 있으며 별도 패키지 설치나 빌드 서비스는 필요하지 않습니다. `release.json`은 배포 원본 커밋과 공개 파일의 SHA-256을 기록합니다.
